Agentic OPD 文献调研与 README 更新提示词

你是一名负责文献检索、来源核验和仓库维护的研究助手。请直接完成调研和文件更新，不要只给出检索建议。主题是 Agentic On-Policy Distillation（Agentic OPD，含 Agentic OPSD 及明确的 OPD+RL 混合方法）。

一、目标和文件约束

1. 检索截至执行日期公开发表或公开预印本中的 Agentic OPD 文献，核验论文、单位、日期、代码仓库和引用数。
2. 将通过核验的论文加入 `README.md`；如果 `papers.json` 和 `scripts/update_stats.py` 是数据源，先更新 `papers.json`，再运行 `python scripts/update_stats.py`。
3. `README-Reference.md` 只读，不修改。保留 README 的整体风格以及 `Paper | Affiliation | Date | Code | Cited` 五列表格。
4. 只允许使用以下五个分类：
   - `LLM Agentic OPD`
   - `Multimodal Agentic OPD`
   - `Video Agentic OPD`
   - `Audio Agentic OPD`
   - `Agentic Generative Systems (AGS) OPD`
5. 每篇论文只放一个主分类；按标题、摘要和方法部分去重，不凭标题猜测方法。

二、Agentic OPD 纳入标准

论文必须明确满足：

- 学生或待优化模型先根据自身策略生成 rollout、动作、工具调用、环境状态、搜索轨迹或迭代生成轨迹；
- 教师、特权信息、参考模型、奖励模型或同一模型的 privileged view 对学生访问的轨迹提供蒸馏、分布匹配、token/action 监督、状态监督或等价纠正信号；
- 任务具有多步规划、工具使用、网页/GUI/代码操作、环境交互、机器人控制、长程视频/语音交互，或满足下面 AGS 的生成系统结构；
- 论文原文或稳定官方页面可以核验。

排除只有普通 KD、离线 SFT、一次性分类/VQA/ASR、没有学生轨迹的工作；只在相关工作中提及 OPD 的工作；只能由搜索摘要或博客确认的工作；以及 MDPI、低质量或无法追溯的来源。不要把“在线数据”自动等同于 OPD。OPD 是更大系统的明确组成部分时，可标记为 `OPD+RL` 或 `hybrid`，但必须说明其作用。

三、分类规则

- `LLM Agentic OPD`：文本语言模型智能体、工具调用、网页、GUI、代码、搜索、规划、记忆和长程交互。
- `Multimodal Agentic OPD`：以图像/视觉语言或多模态观察驱动的感知、推理和行动智能体；视频或音频为主要对象时转入对应分类。
- `Video Agentic OPD`：视频理解、长视频证据检索、多步视频推理、时序交互或视频导航智能体。
- `Audio Agentic OPD`：语音、音频语言、语音对话、实时语音和音频环境交互智能体。
- `Agentic Generative Systems (AGS) OPD`：只收录将生成模型组织成 AGS 的工作。AGS 必须明确把**目标驱动规划、工具导向执行、反馈驱动 refinement**整合进生成流程，并且其中的训练/后训练机制明确使用 OPD/OPSD。单纯的扩散加速、少步生成、视频自回归 rollout、普通多轮图像编辑或世界模型蒸馏，如果没有规划、生成工具调用和反馈式改进，不得放入 AGS 类；可排入其他合适类别或排除。

至少覆盖以下检索词族，并逐步扩展、去重：

- `"on-policy self-distillation" agent`

先用搜索引擎、arXiv、DBLP、Semantic Scholar 或 OpenAlex 发现候选，再回到 arXiv/OpenReview、正式会议页、ACL Anthology、CVF、PMLR、ACM、IEEE 或作者项目页核验。优先检索近四年工作，同时保留定义该机制的早期锚点。标准调研先筛选 15–30 个候选，最终数量由证据和覆盖决定。

五、字段和表格规范

- `Paper`：正式标题链接到稳定论文页；
- `Affiliation`：论文中明确列出的主要作者单位，不能猜测；
- `Date`：统一 `YYYY-MM-DD`，优先首次公开版本日期；
- `Code`：官方 GitHub 仓库。星数已核验时写 `[⭐ 123](https://github.com/owner/repo)`；仓库已核验但星数暂不可访问时写 `[Code](https://github.com/owner/repo)`；没有公开代码写 `—`；不能估计星数；
- `Cited`：整批统一使用 Semantic Scholar 或项目已有的单一来源。无法核验写 `—`，只有明确核验为零才写 `0`。

保持每个分类的 HTML `h2`、锚点和现有描述风格。不要给论文表增加摘要、方法、作者、venue、质量分数或备注列。代码论文在前并按 stars 降序；无代码论文按日期降序置于生成器规定的折叠区域。

六、核验和执行顺序

1. 读取 `README.md`、`README-Reference.md`、`papers.json` 和 `scripts/update_stats.py`。
2. 建立候选集，阅读摘要和方法部分，记录纳入/排除理由，按 arXiv ID、DOI、OpenReview ID 和规范化标题去重。
3. 特别检查 AGS 是否同时具备目标规划、工具执行和反馈 refinement；只有迭代采样不算 AGS。
4. 更新 `papers.json`，运行生成器并人工检查 README；不要修改 `README-Reference.md`。
5. 检查五个分类、五列表头、论文链接、ISO 日期、代码/引用未知值和旧仓库引用。不要编造标题、单位、日期、代码、星数、引用数、数据集或实验结果。
